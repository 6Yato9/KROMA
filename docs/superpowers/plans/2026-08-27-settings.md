# Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remember, between runs, the things that belong to the person rather than to a picture — the set that was open, the effects they have starred, and how they export.

**Architecture:** `apps/windows/src/settings.rs` holds the model and it is already forgiving and forward-compatible. It moves to `pe-session` and stops guessing where to write: `Support` is the host-supplied directory the rest of that crate already uses, and it gives macOS the right place for free.

**Tech Stack:** Rust, the `pe-ffi` C ABI, Swift 6 / SwiftUI, XCTest.

**Predecessors:** the spectral locus. Settings and the eyedropper are what remain of the Windows shell.

---

## The line between this and `@AppStorage`

The Mac already remembers things: which tool is showing, whether the scopes are
open, which panels are folded. Those are **per-shell UI state**, `@AppStorage`
is exactly right for them, and they should stay there.

What moves is what the Windows header calls *things that belong to the person
rather than to any one picture*:

- **favourites** — effect keys, which mean the same in both shells;
- **the session** — the photographs that were open and which was showing;
- **export** — format and quality, because somebody exporting JPEGs at 92 is
  going to keep doing it and asking again every time is asking them to answer a
  question they have already answered.

Those are about the work, they are the same question in both shells, and the
answer should not depend on which one you happened to open.

## Two behaviours to carry across intact

**It swallows errors.** A settings file that fails to parse costs the user their
stars, not their session — every error is swallowed and the defaults stand. That
is a deliberate choice and it needs a test, because the natural instinct when
moving code into a crate that returns `Result` everywhere is to start
propagating.

**It keeps what it does not understand.** `unknown: #[serde(flatten)]` preserves
anything a newer build wrote, so running an older version does not silently
discard it. Also a test — this is the kind of property that survives a move by
luck and then quietly stops working.

## What changes

`Settings::path()` guesses from `APPDATA` or `XDG_CONFIG_HOME`. That is the
opposite of how the rest of `pe-session` works: `Support` is handed in by the
host once at start-up, precisely so the engine never guesses where a user's
files live. Take a `Support` and drop the guessing; the Mac already passes
`~/Library/Application Support/Kroma`.

- [x] **Step 1**

```rust
    pub fn remembered_session(&self) -> (Vec<PathBuf>, usize)
```

`open_paths` and `focus` remember what they did; `set_export` persists.

**A remembered path may no longer exist**, and a photograph that has been moved
or deleted must not stop the others opening. Decide what happens and test it —
Windows' behaviour is the reference, but say what you found rather than assuming
it handles this.

## Task 3: It crosses

**Files:**
- Modify: `crates/pe-ffi/src/lib.rs`

```rust
pe_session_is_favourite(s, key: *const c_char) -> i32     // 1 yes, 0 no
pe_session_toggle_favourite(s, key: *const c_char) -> i32
pe_session_favourites_json(s) -> *mut c_char              // pe_string_free it
pe_session_remembered_session_json(s) -> *mut c_char      // paths and index
```

Follow the sentinel rule: `-1` never reached the session, `-2` refused. JSON for
the lists, because they are cold paths with no count known in advance — the same
argument `pe_session_open_paths` makes.

## Task 4: The Mac uses it

**Files:**
- Modify: `apps/apple/KromaKit/Engine.swift`, `SessionStore.swift`, `EffectBrowser.swift`
- Modify: `apps/apple/PhotoEditor/ContentView.swift`

- [x] **Step 1: Stars**

The effect browser gets a star per effect, and starred ones sort to the top.
`apps/windows/src/inspector.rs` draws its star and sorts by favourite — follow
what it does.

- [x] **Step 2: Reopen what was open**

`ContentView.onAppear` currently opens the test chart unconditionally. It should
open the remembered set if there is one, and fall back to the chart otherwise —
a first run, or a set whose files have all gone.

**Be careful here.** Every existing Swift test that relies on `openTestChart`
being what happens on appear could be affected, and a change that makes the app
open somebody's photographs on launch is one to get right rather than nearly
right.
